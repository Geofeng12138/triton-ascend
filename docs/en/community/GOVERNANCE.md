# Governance

## Mission

As an integral part of the Triton ecosystem, the Triton-Ascend project is dedicated to providing an efficient and user-friendly Triton compilation framework for all Ascend NPU users, enabling Triton code to run efficiently on Ascend hardware, and actively contributing to enriching the Triton and Ascend ecosystem.

## Principles

- **Openness and Transparency**: All technical decisions and community discussions are conducted through public channels.
- **Meritocracy**: Membership is based on individual ability and contributions, not tied to an employer.
- **Community-Driven**: Broad participation is encouraged, diverse perspectives are respected, and consensus is reached through discussion and voting.

## Governance Structure

Triton-Ascend is an open-source project under the Triton community, with role appointments ultimately determined by the Triton community. The project adopts a layered technical governance structure:

### Contributors

**Responsibilities**:

- Help new contributors integrate into the project.
- Handle and respond to community `Issues`.
- Review `RFCs` and code.

**Requirements**:

- Complete at least one contribution.
- Actively and continuously participate in the project by submitting `Issues`, code reviews, code commits, and engaging in community activities.

**Permissions**: Granted the GitHub repository `Triage` role, including read and clone permissions, as well as permissions to submit Issues and PRs.

### Maintainers

**Responsibilities**:

- Define the project's vision and mission, shape the technical direction, and ensure long-term success.
- Possess code merge permissions and lead roadmap planning.
- Review community contributions and continuously improve the codebase.
- Be responsible for the code quality and architectural decisions of core modules.
- Participate in release decisions.
- Mentor contributors through the code contribution process.
- Participate in community technical meetings to discuss and vote on technical direction, major proposals, and `Release` matters.

**Requirements**:

- Have an in-depth understanding of the Triton and Triton-Ascend codebases.
- Demonstrate a commitment to continuous code contribution, with the ability to design, develop, and participate in the PR review process.
- Actively participate in community code reviews, deliver at least one major feature, and maintain a track record of continuous, high-quality contributions.
- Actively handle `Issues`, respond to inquiries, and participate in discussions.
- Make significant technical contributions to the project (e.g., core feature development, architectural design, performance optimization).
- Exhibit sound technical judgment and community collaboration skills.

**Permissions**: Granted write permissions to the GitHub repository, including read, clone, and push permissions, core branch protection and merge permissions, release execution permissions, and permissions to manage `Issues` and `Pull Requests`.

Promotion is jointly reviewed by existing `Maintainers`, considering the quality and continuity of contributions, as well as community engagement.

## Nomination and Removal

### Principles

- Membership is based on individual ability, demonstrated through contributions, reviews, and discussions.
- Candidates must align with the principles of Triton-Ascend and maintain consistent behavior.
- A `Maintainer` who has not contributed to the project for **6 consecutive months** may be transitioned to emeritus status.
- Membership is granted to individuals and is not tied to an employer.

### Nomination Process

- Anyone can initiate a nomination, including self-nomination, via a community `Issue`.
- The nomination must include the candidate's contribution record and a description of their technical capabilities.
- Existing `Maintainers` will review and evaluate the nomination. Approval requires **agreement from more than half of the current Maintainers and no objections**.

### Periodic Review

- The activity of all `Maintainers` is reviewed **monthly** during technical meetings.
- A `Maintainer` who has not contributed to the project for **6 consecutive months** may be transitioned to emeritus status after discussion.
- An `Emeritus` `Maintainer` can apply to restore their `Maintainer` status at any time by resuming active contributions.
